# 채움

공급처가 제각각으로 보낸 상품 소개 글(또는 단가표 그림·PDF)에서 등록 양식 칸을 채우고, 틀릴 만한 칸에 까닭을 붙여 사람 검수로 보내는 서버와 화면이다.
가상 마켓 "응원장터"와 직접 만든 합성 자료로 돈다. 실제 서비스에 붙인 것이 아니다.

- 글 → 뽑기(LLM) → 맞추기(코드) → 따지기(코드) → 갈래(확인 필요 / 바로 승인 가능) → 사람 검수 → 등록 → 영어·중국어 글 → CSV
- Next.js(App Router) + TypeScript + PostgreSQL 16 + Anthropic API
- 무엇을 왜 만드는지는 `docs/PRD.md`, 고른 것과 버린 것은 `docs/DECISIONS.md`, 재는 기준은 `docs/EVAL-SPEC.md`, 잰 값은 `docs/EVALUATION.md`

## 로컬에서 돌리기

Node.js 22 이상과 PostgreSQL 16이 있어야 한다. 개발용 DB와 시험용 DB(이름이 `_test`로 끝나야 한다)를 하나씩 만들어 둔다.

```bash
git clone <이 저장소 주소> && cd chaeum
npm install
cp .env.example .env.local   # DB 주소 둘을 적는다. API 키와 하루 상한은 선택이다
npm run db:migrate
npm run db:seed              # 본보기 공간, 보기 글 12건, 미리 받아 둔 응답
npm run dev                  # http://localhost:3000
npm run verify               # 타입 · 린트 · 시험 · DB 시험 · 빌드 · 묶음 검사 · 녹화 재채점
```

- API 키가 없어도 돈다. 보기 글은 미리 받아 둔 실제 응답으로 뜨고, 직접 넣은 글은 "규칙만"으로 뽑혀 그렇게 표시된다. 그림·PDF는 받지 못한다.
- 직접 넣은 글·그림에 진짜 LLM을 돌리려면 `.env.local`에 API 키와 하루 상한(`.env.example` 참고)을 적는다. 가장 작은 모델을 쓴다.
- 줄을 따로 굴리려면 `npm run worker`. 띄우지 않아도 화면이 요청으로 줄을 굴린다.
- 시험용 DB의 이행은 `npm run test:db`가 알아서 적용한다.

## 폴더

| 자리 | 든 것 |
|---|---|
| `src/contract` | 약속: 칸과 종류, 사유, 상태 이동, API 꼴, 상한 |
| `src/core` | 판단 코드: 단위 맞추기, 검사, 규칙만 뽑기, 갈래. 시계와 난수를 직접 읽지 않는다 |
| `src/llm` | LLM 자리 하나에 구현 셋(실제 호출 / 녹화 재생 / 시험용), 프롬프트 |
| `src/content` | 영어·중국어 글 만들기와 글 검사 |
| `src/server` | 접수, 작업 줄, 초안과 변경 기록, 상품, 내려받기 |
| `app`, `components` | API 경로 18개와 화면 |
| `eval` | 평가기, 주입 시험, 녹화 재채점 |
| `data` | 보기 글, 용어집, 양식 맞춤 파일, 녹화본, 연습 세트 |

## 지금 되어 있는 것과 아닌 것

숨기지 않고 적는다. 날짜는 2026-10-13 기준이다.

되어 있는 것
- 접수(한 건, 여러 건 50건까지, 그림·PDF), 뽑기부터 등록까지의 한 바퀴, 검수 API와 화면, 변경 기록, 동시에 누르면 한쪽은 409
- 영어·중국어 제목·요약과 글 검사 5종, 양식 맞춤 파일로 칸 이름과 순서를 바꾸는 CSV, 번역 검사 API
- PostgreSQL 작업 줄(집기·임대·재시도·죽은 작업), 하루·공간·크기 상한
- 주입 시험 한 번(모델 호출 0번): 여덟 종류 가운데 일곱은 넣은 곳을 다 잡았고, 혼잣말 넣기는 32곳 가운데 20곳을 잡았다. 표는 `docs/EVALUATION.md`

아직 아닌 것
- **지표 여섯은 바깥에 내놓는 묶음(안 여는 세트, 실제 자료, 손글) 어디에서도 아직 내지 못했다.** 정답 세트의 사람 확인이 끝나지 않았다(연습 40건 가운데 20건). 확인한 연습 20건으로는 쟀지만 고칠 때 보는 숫자라 여기에 옮기지 않는다(고친 것과 버린 것은 `docs/EVAL-LOG.md`). 안 여는 세트는 돌리지 않았고, 실제 자료 20건과 손글 10건은 아직 없다.
- **`npm run verify`의 마지막 단계(녹화 재채점)는 사람이 확인한 연습 20건만 지킨다.** 기준 파일(`eval/baseline.json`)은 2026-10-13에 처음 적었고, 그 20건에서 "전부 맞은 문서 수"가 기준 아래로 내려가면 실패한다. 확인 전 20건과 안 여는 세트는 지키지 않는다.
- 공개 배포를 하지 않았다. 무료 호스팅의 한도에서 도는지 재지 않았다.
- 성적표 화면은 묶음마다 방식별로 가장 새 실행 하나를 보여 준다. 평가를 돌린 개발 DB에서 지금 보이는 연습 묶음 실행은 사람이 확인한 20건을, 재 보고 버린 프롬프트 판과 커밋하지 않은 코드로 잰 것이다. 앱이 쓰는 판의 숫자가 아니다. 화면이 "묶음을 다 채점한 실행이 아니다", "커밋하지 않은 변경이 있는 코드로 잰 실행이다"라고 경고한다. 내세우는 숫자가 아니다. 옛 정답(1판)으로 잰 연습 3건 실행은 기록으로만 남아 있다.
- 로그인·권한·결제·주문·정산, 웹 수집, 주소→좌표는 만들지 않는다. 방문자는 추측하기 어려운 작업 공간 번호 하나로만 나뉜다. 요청 횟수 제한은 없다.
- 그 밖의 알고 있는 약점은 `docs/DECISIONS.md` 4절에 있다.

## AI를 쓴 방식

코드와 문서의 초안은 AI 코딩 도구가 썼다. 무엇을 만들지와 범위는 사람이 정했다. 사람이 맡기로 한 일(정답 확인, 실제 자료 모으기, 손글 쓰기, 칸 하나 직접 더하기) 가운데 저장소에 흔적이 있는 것은 정답 확인뿐이고, 그것도 하는 중이다(연습 40건 가운데 20건).
