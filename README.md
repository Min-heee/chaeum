# 채움

공급처가 제각각으로 보낸 상품 소개 글(또는 단가표 그림·PDF)에서 등록 양식 칸을 채우고, 틀릴 만한 칸에 까닭을 붙여 사람 검수로 보내는 서버와 화면이다.
가상 마켓 "응원장터"와 직접 만든 합성 자료로 돈다(모으기 도구의 공공 자료 30줄만 실제 자료다). 실제 서비스에 붙인 것이 아니다. 가수·그룹·업체 이름은 모두 지어낸 것이고, 같은 이름의 실제 업체나 상표가 있더라도 무관하다.

- 글 → 뽑기(LLM) → 맞추기(코드) → 따지기(코드) → 갈래(확인 필요 / 바로 승인 가능) → 사람 검수 → 등록 → 영어·중국어 글 → CSV
- Next.js(App Router) + TypeScript + PostgreSQL 16 + Anthropic API
- 딸린 도구 여섯: 점검, 용어 사전, 견적, 시안 검사, 달력, 모으기(공공 자료를 받아 정리하는 파이썬 수집기 포함). 본체가 채운 칸을 그대로 읽어 쓴다
- 무엇을 왜 만드는지는 `docs/PRD.md`·`docs/PRD-TOOLS.md`, 고른 것과 버린 것은 `docs/DECISIONS.md`, 재는 기준은 `docs/EVAL-SPEC.md`, 잰 값은 `docs/EVALUATION.md`·`docs/EVALUATION-TOOLS.md`, 수집기는 `docs/COLLECTOR.md`

## 로컬에서 돌리기

Node.js 22 이상과 PostgreSQL 16이 있어야 한다. 개발용 DB와 시험용 DB(이름이 `_test`로 끝나야 한다)를 하나씩 만들어 둔다.

```bash
git clone <이 저장소 주소> && cd chaeum
npm install
cp .env.example .env.local   # DB 주소 둘을 적는다. API 키와 하루 상한은 선택이다
npm run db:migrate
npm run db:seed              # 본보기 공간: 보기 글 12건, 본보기 상품 7건, 용어 15줄, 모은 줄 30줄, 미리 받아 둔 응답
npm run dev                  # http://localhost:3000
npm run verify               # 타입 · 린트 · 시험 · DB 시험 · 빌드 · 묶음 검사 · 녹화 재채점
```

- API 키가 없어도 돈다. 보기 글은 미리 받아 둔 실제 응답으로 뜨고, 직접 넣은 글은 "규칙만"으로 뽑혀 그렇게 표시된다. 그림·PDF는 받지 못한다.
- 직접 넣은 글·그림에 진짜 LLM을 돌리려면 `.env.local`에 API 키와 하루 상한(`.env.example` 참고)을 적는다. 가장 작은 모델을 쓴다.
- 줄을 따로 굴리려면 `npm run worker`. 띄우지 않아도 화면이 요청으로 줄을 굴린다.
- 시험용 DB의 이행은 `npm run test:db`가 알아서 적용한다.
- 수집기(파이썬 3.12)는 따로 돈다. 실행 명령은 `collector/README.md`, 시험은 `npm run verify:collector`(가상 환경이 없으면 건너뛴다).

## 폴더

| 자리 | 든 것 |
|---|---|
| `src/contract` | 약속: 칸과 종류, 사유, 상태 이동, API 꼴, 상한 |
| `src/core` | 판단 코드: 단위 맞추기, 검사, 규칙만 뽑기, 갈래. 시계와 난수를 직접 읽지 않는다 |
| `src/llm` | LLM 자리 하나에 구현 셋(실제 호출 / 녹화 재생 / 시험용), 프롬프트 |
| `src/content` | 영어·중국어 글 만들기와 글 검사 |
| `src/tools` | 딸린 도구의 판단 코드(총액·마감·규격 견주기·점검). 순수 함수와 시험 |
| `src/server` | 접수, 작업 줄, 초안과 변경 기록, 상품, 내려받기, 딸린 도구의 DB 일 |
| `app`, `components` | API 경로 32개(본체 18 + 딸린 도구 14)와 화면 |
| `collector` | 파이썬 수집기: 받기, 인코딩 판별, 칸 맞추기, 중복 빼기, 서버로 보내기 |
| `eval` | 평가기, 주입 시험, 녹화 재채점 |
| `data` | 보기 글과 보기 문의, 용어집, 기념일, 양식 맞춤 파일, 녹화본, 연습 세트, 공공 자료 본보기 30줄 |

## 지금 되어 있는 것과 아닌 것

숨기지 않고 적는다. 날짜는 2026-10-13 기준이다.

되어 있는 것
- 접수(한 건, 여러 건 50건까지, 그림·PDF), 뽑기부터 등록까지의 한 바퀴, 검수 API와 화면, 변경 기록, 동시에 누르면 한쪽은 409
- 영어·중국어 제목·요약과 글 검사 5종, 양식 맞춤 파일로 칸 이름과 순서를 바꾸는 CSV, 번역 검사 API
- PostgreSQL 작업 줄(집기·임대·재시도·죽은 작업), 하루·공간·크기 상한
- 주입 시험 한 번(모델 호출 0번): 여덟 종류 가운데 일곱은 넣은 곳을 다 잡았고, 혼잣말 넣기는 32곳 가운데 20곳을 잡았다. 표는 `docs/EVALUATION.md`
- 딸린 도구 여섯의 API 와 화면, XLSX 내려받기. AI 를 쓰는 것은 견적뿐이다(조건 읽기, 답장 쓰기. 돈과 날짜는 코드가 센다). 직접 지은 문의 20건에서 조건 여덟 칸이 모두 맞은 것 19건, 본보기 상품으로 돌리면 10건은 맞는 상품이 없다(지역을 글자로만 견준다). 정답은 지은 쪽이 정했고 사람 확인 전이다. 표는 `docs/EVALUATION-TOOLS.md`
- 수집기: 공공 자료 12개(148,111줄)를 정리해 125,889줄을 만들고, 그 가운데 1,998줄을 로컬 서버로 실제로 보냈다. 표는 `docs/COLLECTOR.md`

아직 아닌 것
- **내세울 지표 여섯은 아직 없다.** 정답 세트의 사람 확인이 끝나지 않았다. 2026-10-13 새벽의 연습 세트 실행은 40건 가운데 사람이 확인한 20건만 채점했다(확인 전 20건은 뺐다). 확인이 진행 중이라 성적표 화면의 수가 이 문서보다 앞설 수 있다. 확인 기록은 개발 DB 에 쌓이는 중이고 저장소의 파일(`data/gold/reviews.jsonl`)로는 아직 내보내지 않았다. 안 여는 세트는 돌리지 않았고, 실제 자료 20건과 손글 10건은 아직 없다.
- **`npm run verify`의 마지막 단계(녹화 재채점)는 지금 아무것도 지키지 않는다.** 기준 파일이 없고, 저장소에 확인 기록 파일도 없어 "채점할 문서 0건 · 기준 없음"으로 지나간다. 기준은 정답 확인 뒤 연습 40건을 다시 녹화해서 만든다. 그 전의 "verify 통과"는 타입·린트·시험·빌드·묶음 검사까지의 통과다.
- 공개 배포를 하지 않았다. 무료 호스팅의 한도에서 도는지 재지 않았다.
- 성적표 화면에 보이는 것은 연습 세트의 실행이다. 2026-10-13 새벽 기준으로 사람이 확인한 20건만 정답 2판으로 채점한 실행(#4~)이 맨 위에 보이고, 그 앞의 연습 3건 실행(#1~3)은 옛 정답(1판)에 확인 전 문서를 넣어 잰 것이다. 연습 세트의 수는 고칠 때 보는 숫자이지 내세우는 숫자가 아니다(이 문서와 `docs/EVALUATION.md`에 싣지 않는다).
- 딸린 도구에서 안 된 것: 용어 후보와 칸 대응을 AI 가 제안하는 기능은 만들지 않았다. 견적의 "보내기"는 표에 적는 것까지다. 수집기는 공개 사이트에서 돌지 않고(본보기 30줄만 실려 있다), 실제 포털에서 내려받는 길은 가짜 서버로만 시험했다. 모은 자료에는 가격이 없다. 시안 검사는 실제 제작 도구에서 나온 파일로 시험하지 않았다. 도구 화면을 지키는 자동 시험은 없다. 본보기 공간의 상품 7건은 사람이 아니라 씨앗이 승인해 둔 것이다(도구가 빈 화면이 되지 않게). 용어 사전의 공용 15줄도 씨앗이 승인 상태로 실은 것이고, 그 중국어 표기는 읽을 줄 아는 사람이 확인하지 않았다. 견적 답장은 아라비아 숫자와 목록에 있는 수 낱말만 검사한다(말로 쓴 숫자를 다 잡지는 못한다)
- 로그인·권한·결제·주문·정산, 실제 판매 사이트 수집, 주소→좌표는 만들지 않는다. 방문자는 추측하기 어려운 작업 공간 번호 하나로만 나뉜다. 요청 횟수 제한은 없다.
- 그 밖의 알고 있는 약점은 `docs/DECISIONS.md` 4절에 있다.

## AI를 쓴 방식

코드와 문서의 초안은 AI 코딩 도구가 썼다. 무엇을 만들지와 범위는 사람이 정했다. 사람이 맡기로 한 일(정답 확인, 실제 자료 모으기, 손글 쓰기, 칸 하나 직접 더하기) 가운데 한 흔적이 있는 것은 정답 확인뿐이고, 그것도 하는 중이다(2026-10-13 새벽에 연습 40건 가운데 20건. 기록은 개발 DB 에 있고 저장소 파일로는 아직 내보내지 않았다).
