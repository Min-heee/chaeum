# 평가 기록 — 고친 것과 버린 것

- 한 번에 한 가지만 바꾸고, 연습 세트에서 건별 나아짐·나빠짐을 본 뒤 여기에 적는다. 버린 시도도 지우지 않는다.
- 연습 세트의 점수는 고칠 때 보는 숫자다. 이 문서 밖(README, 평가 보고)에 옮기지 않는다.
- 안 여는 세트(`test`, `real`)는 파이프라인을 얼린 뒤 한 번 돌린다. 몇 번 돌렸는지는 `eval_runs` 표로 드러난다.
- 기준과 지표의 뜻은 `docs/EVAL-SPEC.md`, 명령은 `docs/EVALUATION.md`의 "돌리는 법"에 있다.

## 적는 틀

시도마다 아래 틀을 복사해 채운다. 숫자는 실행 기록(`eval/results/*.md`)에서 옮기고, 분자/분모를 함께 적는다.

```
### 시도 N — (한 줄 제목)

- 날짜:
- 바꾼 것(한 가지):
- 왜 바꿨나(어느 문서의 어느 칸을 보고):
- 견준 실행: 앞 실행 번호 → 뒤 실행 번호 (묶음 dev, 정답 v_, 모델, 프롬프트 버전, 커밋)
- 문서: 나아짐 _건 / 나빠짐 _건 / 그대로 _건
  - 나아진 문서:
  - 나빠진 문서:
- 칸: 나아짐 _칸 / 나빠짐 _칸
- 쓴 돈: $_ (실제 호출 _건)
- 결정: 채택 / 버림
- 이유:
```

### 시도 1 — 글에 선언된 금액 단위를 따른다

- 날짜: 2026-10-13
- 바꾼 것(한 가지): 글에 금액 단위가 선언돼 있으면("단위: 천원", "(단위: 만원)", "단위 : 원") 그 가까이에 단위 없이 적힌 금액을 그 단위로 읽는다. 맞추기 코드만 바꿨다. 프롬프트, 다른 칸의 맞추기, 막는 사유 목록, 정답은 그대로다. 규칙의 자세한 꼴은 `docs/EVAL-SPEC.md` 문서 이력 v1.3.
- 왜 바꿨나(어느 문서의 어느 칸을 보고): dev-029 수량 옵션. "Price list (단위: 천원)" 아래의 "100 잔 550"을 코드가 만원으로 짐작해 5,500,000원을 냈다(정답 550,000원). 코드 값이 모델 값보다 먼저 실리기 때문에 모델이 옳게 읽어도 틀린 값이 나갔다.
- 견준 실행: 4 / 5 / 6 → 13 / 14 / 15 (묶음 dev 20건, 정답 v2, claude-haiku-5-5, extract-v1, 커밋 91dc883 → edee1dd + 안 올린 변경)
- 문서(`llm_code`): 나아짐 1건 / 나빠짐 0건 / 그대로 19건
  - 나아진 문서: dev-029
  - 나빠진 문서: 없음
- 칸(`llm_code`): 나아짐 1칸 / 나빠짐 0칸 (dev-029 수량 옵션 틀림 → 맞음, 5,500,000 → 550,000)
- 전·후(`llm_code`): 칸 208/212 → 209/212, 전부 맞은 문서 16/20 → 17/20, 지어낸 값 0/52 → 0/52, 바로 승인 줄 5/20 → 5/20(그 안의 틀린 것 0/5 → 0/5), 검사기 포착 4/4 → 3/3, 헛경보 25/208 → 26/209
- 전·후(`rules`): 칸 122/212 → 124/212, 전부 맞은 문서 1/20 → 1/20, 지어낸 값 0/52 → 0/52, 포착 41/90 → 39/88, 헛경보 9/122 → 11/124, 놓친 값 77/212 → 78/212
  - 문서: 나아짐 0건 / 나빠짐 0건 / 그대로 20건. 칸: 나아짐 2칸(dev-029 판매가·수량 옵션) / 나빠짐 0칸 / 틀린 채 판정만 바뀜 1칸
  - 판정만 바뀐 칸: dev-032 기간 옵션 틀림 → 놓침. 규칙이 유동인구 "한 달 690만"을 값표의 한 줄로 잘못 집은 칸이다. 전에는 틀린 값(30일 6,900,000원)을 냈고, 지금은 한 표에 단위가 적힌 줄과 선언을 따른 줄이 섞였다고 보아 못 읽은 것으로 둔다.
- 전·후(`llm_only`): 칸 209/212, 전부 맞은 문서 16/20 그대로. 코드 맞추기를 거치지 않는 방식이라 바뀔 것이 없다.
- 쓴 돈: $0 (실제 호출 0건, 녹화본에서 읽음 20건)
- 결정: 채택
- 이유: 고른 문서가 나아졌고(dev-029) 세 방식 모두에서 나빠진 문서·칸이 0이다. 지어낸 값과 "바로 승인 줄 안의 틀린 것"은 0 그대로다.
- 숨기지 않을 것:
  - 헛경보 분자가 늘었다(`llm_code` 25 → 26). 새로 맞게 된 dev-029 수량 옵션에 `UNIT_CONVERTED`가 붙어서다. 단위를 다른 곳에서 가져왔으니 사람이 보게 한다는 뜻이고, 그래서 dev-029는 전부 맞았어도 바로 승인 줄에 들지 않는다(5/20 그대로). 포착이 4/4 → 3/3 인 것은 틀린 칸이 하나 줄어서다.
  - dev-029 판매가(`llm_code`)는 전에도 지금도 "맞음 + `PARSE_FAILED`"다. 모델이 원문 표현을 "100 잔 550"(수량과 금액이 함께)으로 줘서 코드는 금액 하나로 읽지 못한다. 이번 규칙과 무관해 건드리지 않았다.
  - 남은 틀린 문서 3건(dev-004 갈래, dev-008 기간 옵션, dev-014 이름·위치)은 그대로다.
  - 연습 20건에서 선언이 있는 글은 3건뿐이다(dev-005, dev-032 "단위: 만원", dev-029 "단위: 천원"). "단위: 원" 선언, 영어·중국어 선언, 표 머리 뒤에 빈 줄이 있는 글은 한 건도 없어 그 갈래들은 단위 시험으로만 확인했다.
- 첫 판에서 최종 판 사이에 고친 것(지어낸 글을 넣어 찔러 본 결과. 첫 판의 실행 7 / 8 / 9 와 최종 판은 위 dev-032 한 칸만 다르다):
  - 선언(천원·만원) 아래에 이미 원으로 적힌 큰 수("1,500,000")가 1,000~10,000배가 됐다. → 1만 이상인 수는 곱하지 않고 `PARSE_FAILED`.
  - 선언을 글 전체에 걸어서 "매출 실적(단위: 백만원)"이 다른 단락의 판매가를 바꿨다. → 선언은 같은 줄·같은 단락의 아래 줄·표 머리 바로 다음 단락에만 건다. 만원보다 큰 선언은 상품 값의 단위로 쓰지 않는다(`PARSE_FAILED`).
  - "단위: 천원 미만 절사", "단위: 만원 이상 주문", "천원 아님", "(천원 단위)로 받습니다", "per unit: KRW 1,000", "Order unit: …", "in thousand won-style"을 선언으로 읽었다. → 선언 뒤에 올 수 있는 말을 좁히고 영어 "unit" 앞 낱말을 본다. "(단위: 원, 천원)"은 둘 다 선언으로 보아 `PARSE_FAILED`.
  - "단위: 원" 아래의 큰 금액에 값은 그대로인데 `UNIT_CONVERTED`가 붙었다. → 1만 이상이면 선언이 없을 때와 같게 읽는다(표시 없음).
  - 한 값표에 "150만원"과 단위 없는 "280"이 섞이면 줄끼리 어긋난 값이 됐다. → 표 전체를 `PARSE_FAILED`.
  - 시험이 놓치던 변이를 메웠다. 저장소 밖 복사본에서 변이 51개를 넣어 50개가 시험에 걸렸다. 남은 1개는 동작이 같은 변이다(단위 낱말을 찾는 순서).
- 주입 시험 기록(`eval/results/inject.json`)을 다시 냈다. 달라진 곳은 망가뜨리기 전 값 재료 216칸 → 218칸, 그 가운데 원래부터 표시가 붙은 칸 16칸 → 18칸 둘뿐이다(dev-029의 두 칸이 재료로 들어왔고, 표시가 붙은 칸이라 망가뜨릴 곳에서는 빠진다). 종류별 잡은 수와 못 잡은 12곳은 같다.
- 회귀 문지기의 기준 파일(`eval/baseline.json`)을 처음 적었다: `llm_code` 전부 맞은 문서 17/20. 깃발 없이 돌리면 통과(exit 0), 기준을 18로 올려 보면 실패(exit 1)인 것을 확인하고 되돌렸다.
- 한계(다음에 볼 것):
  - 경계 1만은 전부터 쓰던 "만원 짐작" 경계를 그대로 빌린 것이다. "단위: 천원" 아래의 "15,000"(1,500만원)처럼 정당한 큰 수도 못 읽은 것으로 간다. 경계를 어디에 둘지는 사람이 정한다.
  - 표 머리와 값 사이에 다른 단락이 끼면 선언이 걸리지 않아 전처럼 만원으로 짐작한다(표시는 붙는다).
  - 같은 단락 안에서는 여전히 상관없는 선언이 걸릴 수 있다. "포인트 적립 (단위: 원) 은 1%입니다" 바로 아래 줄의 "가격 550"은 550원이 된다(표시는 붙는다).
  - 놓치는 선언 꼴: "금액(천원)" 표 머리, "(단위: 명, 천원)", "가격 단위가 천원입니다", "아래 표 단위: 천원", 줄이 바뀐 선언. 놓치면 전과 같은 동작이다.
  - 외화 선언("Unit: USD", "单位：元") 아래의 단위 없는 수를 만원으로 짐작한다. 이번 회차 전부터 있던 동작이다.
  - 선언이 없을 때 "1,500.5" → 15,005,000원, "-550" → 5,500,000원(음수 부호를 버림)도 전부터 있던 동작이다.
  - `UNIT_CONVERTED`의 사람용 설명("빠진 단위(만원)를 짐작해 적었습니다")이 선언된 천원·원을 따른 경우와 조금 어긋난다. 막는 사유 목록을 건드리는 일이라 이번에는 두었다.
