# 일치 기준과 지표 — EVAL-SPEC v1

- 이 문서는 평가기와 파이프라인 구현보다 먼저 커밋된다. 커밋 순서가 그 증거다.
- 구현 뒤에는 바꾸지 않는다. 바꾸게 되면 맨 아래 "문서 이력"에 날짜, 바꾼 것, 이유, 영향을 받는 숫자를 적는다.
- 꼴(타입)은 `src/contract/eval-types.ts`, 칸과 값의 꼴은 `src/contract/fields.ts`에 있다. 글과 코드가 어긋나면 이 글이 기준이다.
- 이 문서에는 잰 숫자가 없다. 기준만 있다.

## 1. 무엇을 무엇과 견주나

- 한 문서에서 견주는 것은 **맞춘 뒤의 표준 값**이다. 원문 표현끼리 견주지 않는다.
- 견주는 방식은 셋이고, 같은 문서와 같은 LLM 호출에서 나온다.

| 방식 | 낸 값으로 치는 것 | 표시(사유) |
|---|---|---|
| `rules` 규칙만 | 정규식으로 찾은 원문 표현을 코드가 맞춘 값 | 있음 |
| `llm_only` LLM만 | 모델이 읽은 값 그대로(`modelValue`) | 없음 |
| `llm_code` LLM 뽑기 + 코드 맞추기 | 초안에 실리는 값(`finalValue`): 코드가 맞춘 값, 그것이 없으면 모델 값 | 있음 |

- `rules`와 `llm` 계열의 차이를 "개선"이라고 부르지 않는다. 기준선 규칙을 대충 짤수록 커지는 숫자다. 규칙이 이긴 칸이 있으면 그대로 싣는다.

## 2. 채점하는 문서와 칸

**문서**
- 사람이 확인한 문서만 채점한다. 가장 최근 첫 확인(`pass = 1`)의 판정이 `ok` 또는 `fixed`인 문서다.
- 확인 기록이 없는 문서와 `dropped`(버림) 문서는 뺀다. 뺀 건수를 결과와 함께 적는다.
- 네 묶음(연습 `dev` / 안 여는 세트 `test` / 실제 자료 `real` / 손글 `hand`)의 점수를 **합치지 않는다.** 합계 줄을 만들지 않는다.

**칸**
- 채점하는 칸은 **정답의 종류**에 딸린 칸이다(광고 지면 16, 케이터링 8, 굿즈 8, 등록 대상 아님 0).
- 낸 종류가 정답의 종류와 다르면:
  - 정답 종류의 칸 가운데 낸 결과에 없는 칸은 "없음"을 낸 것으로 친다.
  - 낸 종류에만 있는 칸은 칸 지표에 넣지 않는다. 종류가 틀린 것은 종류 정확도와 "전부 맞은 문서"에서 드러난다.
- 정답이 "등록 대상 아님"인 문서는 채점할 칸이 없다. 종류를 맞혔는지만 본다.
- 종류와 갈래는 칸 지표(1·2·5번)에 넣지 않는다. 결과 표에는 `type`, `subtype` 줄로 남긴다.

## 3. "없음"

- 정답의 "없음"은 `null`이다. 정답에는 빈 목록과 빈 글을 쓰지 않는다.
- 낸 값이 아래 가운데 하나면 "없음"을 낸 것으로 친다.
  - `null`이거나 칸이 아예 없음
  - 빈 목록 `[]`
  - 정리(5절)한 뒤 빈 글이 되는 글
- 표준 꼴이 아닌 값(예: 금액 칸에 글자)은 "없음"이 아니라 **다른 값**이다. 정답에 값이 있으면 `wrong`, 없으면 `fabricated`.

## 4. 칸 하나의 판정

| 정답 | 낸 값 | 판정 |
|---|---|---|
| 값 있음 | 일치 | `correct` |
| 값 있음 | 다른 값 | `wrong` |
| 값 있음 | 없음 | `missed` |
| 없음 | 값 있음 | `fabricated` |
| 없음 | 없음 | `true_none` |

"틀린 칸"은 `wrong` + `missed` + `fabricated`다. "맞은 칸"은 `correct`다. `true_none`은 둘 어디에도 넣지 않고 따로 센다.

## 5. 칸별 일치 규칙

글자 정리(이름 칸에 쓴다): ① NFKC로 글자 꼴 통일 ② 영문은 소문자로 ③ 괄호 글자 `( ) [ ] { } < > 「 」 『 』 【 】`를 지움(안의 글은 남김) ④ 공백(띄어쓰기·탭·줄바꿈)을 모두 지움.

| 값의 갈래 | 칸 | 일치 |
|---|---|---|
| 금액 | `price_krw`, `list_price_krw` | 원 단위 정수가 같다. 허용 오차 없음 |
| 참·거짓 | `vat_included` | 같다 |
| 이름(글자) | `name`, `region`, `service_region`, `material` | 정리한 글이 **완전히 같다.** 한쪽이 다른 쪽을 품는 것(포함 관계)은 틀림 |
| 크기 m | `size_m` | 가로끼리, 세로끼리 각각 `|낸 값 − 정답| ≤ 정답 × 0.01`. 가로와 세로가 뒤바뀐 것은 틀림 |
| 크기 mm | `size_mm` | 위와 같음(1% 이내) |
| 해상도 | `resolution_px` | 가로와 세로가 각각 같다 |
| 시간 | `hours`, `service_hours` | 시작, 끝, 다음 날 여부가 **모두** 같다 |
| 하루 유동인구 | `footfall_per_day` | `|낸 값 − 정답| ≤ 정답 × 0.05` |
| 횟수·개수 | `spot_seconds`, `plays_per_day`, `min_order_qty` | 정수가 같다 |
| 일수 | `material_deadline_days`, `refund_full_days`, `booking_deadline_days`, `design_deadline_days`, `lead_time_days` | 정수가 같다 |
| 기간 옵션 | `period_options` | (일수, 원) 쌍의 **집합**이 완전히 같다 |
| 수량 옵션 | `quantity_options` | (수량, 원) 쌍의 집합이 완전히 같다 |
| 파일 형식 | `file_format` | 소문자로 바꾸고 앞의 점을 뗀 확장자의 집합이 완전히 같다 |

덧붙임
- 허용 오차의 경계는 포함한다(정확히 1%, 정확히 5%는 맞음).
- 목록 칸은 순서를 보지 않는다. 같은 쌍이 두 번 있으면 한 번으로 친다. 하나가 더 있거나 덜 있으면 틀림이다. 쌍 안의 금액에는 허용 오차가 없다.
- 일수와 유동인구를 바꾸는 규칙은 정답과 구현이 같이 쓴다: 1주 = 7일, 1개월 = 30일, 월 유동인구 ÷ 30, 주 ÷ 7, 연 ÷ 365, 소수는 반올림.
- 금액은 원문에 적힌 금액이다. 부가세를 더하거나 빼지 않는다. 부가세 포함 여부는 `vat_included` 칸으로 따로 채점한다.
- `price_krw`는 대표 판매가다. 옵션이 있으면 가장 짧은 기간(가장 적은 수량) 옵션의 값이 정답이다.

**종류와 갈래**
- 종류: 넷 가운데 같은 것이어야 맞음.
- 갈래: 글자가 같아야 맞음. 정답이 "등록 대상 아님"이면 갈래는 채점하지 않는다.

## 6. 표시

- **칸의 표시**: 그 칸에 "막는 사유"(`src/contract/reasons.ts`에서 `blocking`이 참인 사유)가 하나 이상 붙었다.
- **문서의 표시**: 칸이든 초안 전체든 막는 사유가 하나 이상 있다. 표시 0개인 문서가 "바로 승인 가능"이다.
- 어느 사유가 막는 사유인지는 연습 세트에서 정하고, 안 여는 세트를 돌리기 전에 얼린다. 얼린 뒤에는 바꾸지 않는다.
- `llm_only`에는 표시가 없다. 4번·5번 지표를 내지 않는다.
- `rules` 방식에서는 "규칙만으로 뽑음" 사유를 문서의 표시로 세지 않는다. 세면 모든 문서에 표시가 붙어 4번 지표가 뜻을 잃는다.

## 7. 지표 여섯

모든 비율은 분자/분모와 함께 적는다. 분모가 0이면 비율을 적지 않고 "해당 없음(0건)"이라고 쓴다.

**1. 칸 정확도 (칸별, 그리고 전체)**
- 분자: `correct`인 칸
- 분모: 정답에 값이 있는 칸 = `correct` + `wrong` + `missed`
- 칸 이름별로 낸다. 전체 한 줄도 내지만 칸별 표를 앞에 둔다.

**2. 지어낸 값**
- 분자: `fabricated`인 칸
- 분모: 정답이 "없음"인 칸 = `fabricated` + `true_none`

**3. 전부 맞은 문서**
- 분자: 종류가 맞고, 갈래가 맞고(상품일 때), 채점하는 칸이 모두 `correct`이거나 `true_none`인 문서
- 분모: 채점한 전체 문서
- 정답이 "등록 대상 아님"인 문서는 종류만 맞히면 전부 맞은 것이다.

**4. 바로 승인 줄과 그 안의 틀린 것** (숫자 둘)
- 바로 승인 줄: 표시 0개인 문서 / 전체 문서
- 그 안의 틀린 것: 표시 0개인 문서 가운데 3번의 "전부 맞은 문서"가 아닌 문서 / 표시 0개인 문서

**5. 검사기 포착과 헛경보** (숫자 둘)
- 포착: 표시가 붙은 틀린 칸 / 틀린 칸 전체
- 헛경보: 표시가 붙은 맞은 칸 / 맞은 칸 전체
- 참고로 함께 적는 것: 표시가 붙은 `true_none` 칸 / `true_none` 칸. 필수 칸이 원문에 정말 없어서 붙은 표시는 틀린 것도 헛경보도 아니므로 따로 둔다.
- 초안 전체에 붙는 사유(종류·갈래 불일치 등)는 칸의 표시가 아니다. 4번에서만 센다.

**6. 건당 비용과 시간**
- 비용: 그 실행의 뽑기 호출 비용 합 / 문서 수. 비용 = 토큰 수 × 단가(단가표에 확인한 날짜와 주소를 적는다).
- 시간: 문서별 뽑기 호출에 걸린 시간의 가운데값과 95번째 값. 가장 가까운 순위 방식(작은 것부터 줄 세워 `⌈n × p⌉`번째)으로 낸다.
- 녹화본으로 다시 채점한 실행은 녹화할 때 잰 값을 쓰고 "녹화 때 잰 값"이라고 적는다.
- `rules`는 호출이 없으므로 내지 않는다.

**따로 싣는 것** (`docs/EVALUATION.md`)
- 종류 정확도: 종류를 맞힌 문서 / 전체 문서
- 갈래 정확도: 갈래를 맞힌 문서 / 정답이 상품인 문서
- 놓친 값: `missed`인 칸 / 정답에 값이 있는 칸
- 글 검사 통과율: 검사 5종을 모두 통과한 글 / 만든 글(언어별, 칸별로 따로)
- 지시문이 든 글에서 지시를 따른 건수 / 지시문이 든 글 수

## 8. 두 실행 견주기 (나아짐·나빠짐)

- 같은 묶음, 같은 정답 버전, 같은 방식의 두 실행을 **같은 문서끼리** 견준다.
- 나아짐: 앞 실행에서 전부 맞은 문서가 아니었고 뒤 실행에서 전부 맞은 문서
- 나빠짐: 앞 실행에서 전부 맞은 문서였고 뒤 실행에서 아닌 문서
- 퍼센트의 차이가 아니라 "나아짐 ○건 / 나빠짐 ○건"으로 적는다. 칸 단위로도 같은 방식으로 낼 수 있다.
- 정답 버전이 다른 두 실행은 견주지 않는다.

## 9. 숫자를 적는 법

- 잰 것만 적는다. 모든 비율 옆에 분자/분모를 적는다.
- "○건 중 0건"을 "0%"라고 적지 않는다.
- 연습 세트의 점수는 바깥에 내세우지 않는다. 고칠 때 보는 숫자다.
- 안 여는 세트는 파이프라인을 얼린 뒤 한 번 돌린다(첫 판 프롬프트와 마지막 판을 함께). 몇 번 돌렸는지는 실행 기록 표로 드러난다.
- 실행 기록마다 모델, 프롬프트 버전, 정답 버전, 코드 커밋 번호를 남긴다.
- 평가 뒤 정답이 틀린 것으로 드러나면 정답 버전을 올리고, 몇 건을 왜 고쳤는지 적은 뒤 다시 채점한다. 옛 버전의 결과는 지우지 않는다.

## 10. 주입 시험 (LLM 비용 0)

맞는 값과 통과하는 글을 일부러 망가뜨린 뒤 검사기가 잡는지 본다. 종류별로 **잡은 수 / 넣은 수**를 낸다. 못 잡은 종류는 한계에 적는다.

값을 망가뜨리는 넷 — 재료는 연습 세트의 정답과 원문. "잡았다" = 망가뜨린 칸에 막는 사유가 하나 이상 붙었다.

| 종류 | 망가뜨리는 법 | 잡을 것으로 보는 사유 |
|---|---|---|
| `zero_added` | 모델 값의 금액 끝에 0을 하나 더 붙인다(원문 표현은 그대로) | `VALUE_MISMATCH` |
| `unit_swap` | 크기 값에서 m와 mm를 뒤바꾼다(1000배 또는 1/1000) | `VALUE_MISMATCH` 또는 `OUT_OF_RANGE` |
| `fake_evidence` | 근거 구절을 원문에 없는 문장으로 바꾼다 | `NO_EVIDENCE` |
| `cheaper_longer` | 기간 옵션에서 긴 기간의 총액을 짧은 기간보다 작게 바꾼다 | `OUT_OF_RANGE` |

글을 망가뜨리는 넷 — 재료는 글 검사를 통과하는 제목·요약. "잡았다" = 글 검사 실패 코드가 하나 이상 나왔다.

| 종류 | 망가뜨리는 법 | 잡을 것으로 보는 코드 |
|---|---|---|
| `monologue` | 글 앞이나 뒤에 모델의 혼잣말·머리말 문장을 붙인다 | `MONOLOGUE` |
| `glossary_swap` | 용어집 표기를 다른 낱말로 바꾼다 | `GLOSSARY_MISS` |
| `placeholder_removed` | 자리표시를 지우거나 숫자로 바꿔 적는다 | `PLACEHOLDER_LOST`, `STRAY_NUMBER` |
| `hangul_mixed` | 글 가운데에 한글 낱말을 넣는다 | `HANGUL_IN_TEXT` |

- 망가뜨릴 곳은 씨앗을 고정한 난수로 고른다. 같은 씨앗이면 같은 결과가 나온다.
- "잡을 것으로 보는" 칸은 예상이다. 채점은 "하나라도 붙었는가"로 하고, 예상과 다른 사유로 잡힌 건수는 따로 적는다.
- 망가뜨리지 않은 원본에서 표시가 붙는 수(헛경보)도 함께 낸다.
- 주입 시험은 검사기를 재는 것이다. 모델을 재는 것이 아니다.

## 11. 평가기 자체의 시험

- 답을 아는 가짜 결과를 넣어 지표 여섯이 손으로 센 값과 같은지 본다.
- 일치 규칙의 경계(정확히 1%, 1%를 조금 넘김, 포함 관계, 가로·세로 뒤바뀜, 목록에 하나 더 있음, 빈 목록)를 시험 이름으로 둔다.
